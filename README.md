# Study Planner

Навчальний планувальник на React, Vite та TypeScript.

## Реалізовані можливості

- Список початкових завдань із назвою, описом, категорією та пріоритетом.
- Додавання завдання через форму з перевіркою обов'язкової назви.
- Очищення форми після додавання та категорія «Без категорії», якщо її не вказано.
- Позначення завдання як виконаного та повернення до невиконаного стану.
- Видалення завдань, фільтри «Всі», «Виконані», «Не виконані».
- Загальна кількість завдань, виконаних і невиконаних незалежно від фільтра.
- Окремі повідомлення для порожнього списку та порожнього результату фільтра.
- Адаптивний інтерфейс на SCSS із класами за BEM та стилями за компонентами.

Завдання зберігаються у стані `App` через `useState` та оновлюються незмінно
за допомогою `map` і `filter`. Компоненти отримують дані та callback-функції
через props. Після перезавантаження сторінки відновлюються початкові завдання.

Статистика та відфільтрований список обчислюються з поточного масиву завдань,
без окремого стану для лічильників і без зміни вихідного масиву під час фільтрації.
Порожні назви та назви лише з пробілів не приймаються; крайні пробіли в полях
обрізаються перед додаванням. Нове завдання має стан «Не виконано». Після додавання
вмикається фільтр «Всі», щоб нове завдання одразу було видно у списку.

## Вимоги до середовища

- Node.js 22.22.0 або новіший (мінімальна версія зазначена в `package.json`).
- React та React DOM 19.x (версії залежностей зафіксовані у `package-lock.json`).
- Для розробки використовується Node.js 24.21.0, зазначений у `.nvmrc`.

Якщо встановлено nvm, у папці `study-planner` можна вибрати версію Node.js:

```bash
nvm install
nvm use
```

## Запуск через npm

Усі команди виконуйте в папці `study-planner`.

Встановіть залежності за версіями з `package-lock.json` та запустіть сервер розробки:

```bash
npm ci
npm run dev
```

Відкрийте адресу з термінала (за замовчуванням `http://localhost:5173`).
Якщо порт зайнятий, Vite вибере інший і покаже актуальну адресу.
Щоб зупинити сервер, натисніть `Ctrl+C`.

Для створення production-збірки та її локального перегляду:

```bash
npm run build
npm run preview
```

Збірка зберігається в папці `dist`. Сервер перегляду показує адресу в терміналі
(за замовчуванням `http://localhost:4173`).

## Перевірка TypeScript та ESLint

```bash
npm run typecheck
npm run lint
```

`typecheck` перевіряє типи коду застосунку та конфігурації Vite без створення
production-збірки. Для обох частин проєкту ввімкнено строгий режим TypeScript
(`strict: true`). `lint` перевіряє правила TypeScript, React Hooks та Fast Refresh.

Команда `npm run build` також перевіряє типи перед створенням збірки Vite.

## Структура проєкту

```text
study-planner/
├── src/
│   ├── components/
│   │   ├── Header/     # Заголовок застосунку
│   │   ├── TaskForm/   # Форма додавання та валідація
│   │   ├── TaskFilters/ # Вибір стану завдань для показу
│   │   ├── TaskItem/   # Картка завдання та кнопки керування
│   │   ├── TaskList/   # Список завдань і порожній стан
│   │   └── TaskStats/  # Лічильники з поточного масиву завдань
│   ├── data/
│   │   └── initialTasks.ts # Початкові навчальні завдання
│   ├── types/
│   │   └── task.ts     # Типи Task, TaskPriority, TaskDraft і TaskFilter
│   ├── App.tsx         # Кореневий компонент інтерфейсу
│   ├── App.scss        # Стилі компонування застосунку
│   ├── index.scss      # Базові стилі сторінки
│   └── main.tsx        # Точка входу React, підключення App і базових стилів
├── index.html          # HTML-сторінка з контейнером #root
├── package.json        # Залежності та npm-команди
├── package-lock.json   # Точні версії встановлюваних залежностей
├── vite.config.ts      # Налаштування Vite та React-плагіна
├── tsconfig.json       # Посилання на конфігурації TypeScript
├── tsconfig.app.json   # Налаштування TypeScript для src
├── tsconfig.node.json  # Налаштування TypeScript для vite.config.ts
├── eslint.config.js    # Правила перевірки коду
├── .nvmrc              # Версія Node.js для nvm
└── .gitignore          # Файли й папки, які Git не відстежує
```

Під час запуску `index.html` підключає `src/main.tsx`. У ньому `createRoot`
монтує компонент `App` у контейнер `#root`, а `StrictMode` вмикає додаткові
перевірки React під час розробки. Дочірні компоненти застосунку підключаються з `App`.

Папка `node_modules` містить встановлені залежності, а `dist` — результат збірки.
Обидві створюються командами npm і виключені з Git через `.gitignore`.
