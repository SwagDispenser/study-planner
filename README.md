# Study Planner

Навчальний планувальник на React, Vite та TypeScript. Продовження лабораторної №8:
стан через useReducer і Context API, persistence через localStorage та Effects.
Стилізація — SCSS + BEM, стилі розміщені поруч із компонентами.

## Реалізовані можливості

- Створення, позначення виконання, фільтрація, статистика та порожні стани з №8.
- Редагування назви, опису, категорії та пріоритету через ту саму форму.
- Скасування чернетки редагування без зміни завдання.
- Єдине джерело даних завдань — reducer усередині TaskProvider.
- Context API й useTaskContext замість передачі спільного стану через рівні props.
- Збереження завдань і фільтра після перезавантаження сторінки.
- Перевірка збережених даних: некоректний JSON, неправильні поля або повторні ID
  замінюються початковими даними. Збережений порожній масив є коректним списком.
- Заголовок вкладки з актуальною кількістю невиконаних завдань.
- Видалення з можливістю скасування протягом 5 секунд та візуальним прогресом.
- Toast після додавання, редагування, остаточного видалення, Undo, скидання або помилки операції.
- Кнопка «Скинути дані»: початкові завдання, фільтр «Всі», скасування активного таймера.

## Вимоги до середовища

- Node.js 22.22.0 або новіший (мінімальна версія зазначена в `package.json`).
- React та React DOM 19.x (версії залежностей зафіксовані у `package-lock.json`).
- Для розробки використовується Node.js 24.21.0, зазначений у `.nvmrc`.

Якщо встановлено nvm, у папці `study-planner` можна вибрати версію Node.js:

```bash
nvm install
nvm use
```

## Запуск через npm

Усі команди виконуйте в папці `study-planner`.

Встановіть залежності за версіями з `package-lock.json` та запустіть сервер розробки:

```bash
npm ci
npm run dev
```

Відкрийте адресу з термінала (за замовчуванням `http://localhost:5173`).
Якщо порт зайнятий, Vite вибере інший і покаже актуальну адресу.
Щоб зупинити сервер, натисніть `Ctrl+C`.

Для створення production-збірки та її локального перегляду:

```bash
npm run build
npm run preview
```

Збірка зберігається в папці `dist`. Сервер перегляду показує адресу в терміналі
(за замовчуванням `http://localhost:4173`).

## Перевірка TypeScript та ESLint

```bash
npm run typecheck
npm run lint
npm test
```

`typecheck` перевіряє типи коду застосунку та конфігурації Vite без створення
production-збірки. Для обох частин проєкту ввімкнено строгий режим TypeScript
(`strict: true`). `lint` перевіряє правила TypeScript, React Hooks та Fast Refresh.

Команда `npm run build` також перевіряє типи перед створенням збірки Vite.


## Організація стану

| Місце | Відповідальність |
| --- | --- |
| `state/taskReducer.ts` | Чиста функція з типізованими actions: add, toggle, update, requestDelete, confirmDelete, undoDelete, reset. |
| `context/TaskContext.ts` | Тип спільного API та створення Context. |
| `context/TaskProvider.tsx` | Ініціалізація reducer зі сховища, операції над завданнями, вибір редагованого ID та Effects. |
| `hooks/useTaskContext.ts` | Доступ до Context; зрозуміла помилка поза Provider. |
| `hooks/useLocalStorage.ts` | Узагальнений hook для збереження активного фільтра. |
| `utils/storage.ts` | Ключі сховища, безпечне читання JSON та перевірки структури даних. |
| `components/TaskList/` | Обчислення відфільтрованого списку під час render; повідомлення порожніх станів. |
| `components/TaskStats/` | Обчислення лічильників під час render із повного списку завдань. |
| `components/TaskForm/` | Створення й редагування: локальна чернетка полів, валідація, виклики addTask/updateTask із Context. |
| `components/TaskItem/` | Дані однієї картки через props, операції через Context, стан очікування видалення. |
| `components/Toast/` | Повідомлення та анімація прогресу. Таймерами керує Provider. |
| `components/TaskToolbar/` | Кнопка скидання даних. |
| `tests/` | Тести чистоти reducer, переходів стану, захисту від застарілих actions і пошкодженого сховища. |

App відповідає за компонування. TaskProvider підключений у main.tsx усередині
StrictMode. Компоненти працюють із публічними операціями Context і не керують
таймерами та dispatch самостійно. Props залишаються для даних окремої картки.

## Effects та persistence

- Lazy initializer читає `study-planner.tasks`; якщо дані відсутні або пошкоджені,
  використовує initialTasks. Reducer не звертається до localStorage.
- Effect із залежністю tasks записує лише масив завдань у localStorage. Другого
  React-state для цього масиву немає. Помилка запису показується через Toast.
- useLocalStorage зберігає фільтр у `study-planner.filter` і перевіряє його значення.
- Окремий Effect синхронізує document.title з кількістю невиконаних завдань.
- Статистика й фільтрація не використовують Effects або додатковий state.

## Undoable Delete

requestDelete залишає завдання у списку та записує тимчасовий pendingDeletion
із ID, унікальним token і часом завершення. Картка має приглушений вигляд,
напис «Буде видалено» та заблоковані операції над цим завданням.

Effect запускає setTimeout до завершення 5 секунд. Натискання «Скасувати»
виконує undoDelete, очищує pendingDeletion і через cleanup скасовує таймер.
Після таймера confirmDelete остаточно видаляє завдання та показує Toast.
Cleanup також виконується під час скидання даних, зміни pendingDeletion і unmount.
Token захищає reducer від застарілих confirmDelete/undoDelete.

Одночасно активне лише одне видалення. Інші кнопки видалення тимчасово вимкнені.
Створення завдання або зміна фільтра не перезапускають таймер. Звичайне повідомлення
не замінює Toast із Undo: під час потреби вони показуються поруч у стеку.

pendingDeletion не зберігається в localStorage. Якщо перезавантажити сторінку
до confirmDelete, завдання залишиться у списку без таймера. Остаточно видалені
завдання після перезавантаження не відновлюються. Toast автоматично зникає через
3,5 секунди; повідомлення Undo доступне протягом усього часу видалення.

## Редагування завдання

Кнопка «Редагувати» викликає startEditing(id) із Context. Provider зберігає лише
editingId; актуальне editingTask обчислюється з масиву завдань. Це не другий
список завдань і не копія об'єкта в спільному стані.

TaskForm повторно використовує однакові поля для створення й редагування.
Внутрішній TaskFormFields має key за ID редагованого завдання або `new`:
React заново створює локальну чернетку при зміні режиму чи виборі іншого завдання.
Effect для копіювання props у state не потрібний. Поле назви отримує фокус
під час відкриття редактора.

«Зберегти зміни» перевіряє назву, викликає updateTask та dispatch дії update.
Змінюються лише title, description, category і priority; ID та completed
зберігаються. Після успіху редактор закривається, форма переходить у режим
створення, а Toast повідомляє про збереження. Фільтр залишається обраним.

«Скасувати редагування» відкидає чернетку. Перехід до редагування іншого завдання
також відкидає незбережені поля попереднього. Зміна фільтра або оновлення іншого
завдання не скидає поточну чернетку. Після перезавантаження відновлюються збережені
завдання, а незбережена чернетка не відновлюється.

Для завдання, яке очікує видалення, редагування вимкнено. Видалення поточного
редагованого завдання або «Скинути дані» закриває редактор. Редагування іншого
завдання не перезапускає таймер видалення й не прибирає кнопку Undo.

## Сценарій ручної перевірки

1. Додайте завдання, виберіть «Не виконані» та перезавантажте сторінку:
   нове завдання й активний фільтр повинні зберегтися.
2. Позначте завдання виконаним: статистика та заголовок вкладки оновлюються.
3. Натисніть «Видалити»: завдання ще є у списку, видно стан очікування,
   Toast із прогресом та кнопку «Скасувати».
4. Скасуйте видалення до завершення 5 секунд і зачекайте довше за таймер:
   завдання має залишитися.
5. Повторіть видалення без скасування: через 5 секунд завдання зникає,
   статистика оновлюється, з'являється повідомлення про остаточне видалення.
6. Під час очікування видалення перезавантажте сторінку: завдання залишається,
   а незавершений таймер не відновлюється.
7. Під час очікування видалення натисніть «Скинути дані»: повертаються початкові
   3 завдання (1 виконане, 2 невиконані), таймер не видаляє їх пізніше.
8. Перевірте старі сценарії: порожня назва, очищення форми, три фільтри,
   обидва порожні стани, однакові назви в різних завдань, екран шириною 320 px.
9. Відкрийте редагування виконаного завдання: усі поля заповнені поточними даними.
   Змініть чотири поля та збережіть: ID, completed і лічильники незмінні,
   нові значення зберігаються після перезавантаження, показано Toast.
10. Спробуйте зберегти назву лише з пробілів: зміни не застосовуються.
    Змініть поля та скасуйте редагування: завдання залишається без змін.
11. Перейдіть із редагування одного завдання до іншого, змініть фільтр,
    виконайте Undo та скидання даних: форма має відповідати поточному режиму,
    незбережені поля не повинні потрапляти в інше завдання.
